# QuestRoute 技术说明

本文件保留仍适用于当前代码的数据约束和实现规则，替代按 r2–r13 分散记录的阶段调研。当前 `apiRevision=14`、`schemaVersion=1`；公开参数和返回字段以[插件 README](../addons/QuestRoute/README.md)为准，模块边界见[模块说明](../addons/QuestRoute/MODULES.md)。验证证据与未完成验收分别见[开发进度](../开发进度.md)和[待办事项](../待办事项.md)。

## 原生数据与位置语义

当前任务列表、原始目标文字、`finished`、计数、失败、整项完成和可交状态均以客户端为准。不用计数全满、到达坐标或数据库关系推断任务完成。

`C_QuestLog.GetQuestsOnMap(queryMapID)` 返回任务级 POI。其 `x/y` 属于**查询地图**，返回的 `poi.mapID` 可能仍是关联原图，必须分开保存：

| 字段 | 含义 |
| --- | --- |
| `coordinateMapID` | `x/y` 所属查询地图坐标系 |
| `reportedMapID` | API 返回的 POI 关联地图 |
| `x/y` | 归一化 0..1，显示常见地图坐标时乘 100 |
| `world.continentID/x/y` | 世界坐标，仅相同大陆可比较距离 |
| `source/precision` | `C_QuestLog.GetQuestsOnMap` / `quest_poi` |

原生回退和交付按 `reportedMapID` 判断目标归属，不能因邻图投影落在当前地图内就纳入；可靠细目标按静态位置本身的地图归属判断。世界坐标转换必须使用 `coordinateMapID`，不能只换地图标签。

POI 去重只合并同任务、同标记语义、同大陆且距离不大于 0.1 的点，优先原图记录作为固定代表，避免链式近邻误合并。没有世界坐标时只合并坐标系和坐标完全相同的记录。

未指定地图的查询扫描艾泽拉斯 947 的后代地图，不保证覆盖全部副本；根地图本身不保证返回所有点。POI 的 `inProgress`、`numObjectives` 不能判断真实进度。坐标可能随状态变化，不能永久缓存为实体刷新数据库。

既有普通任务样本中，waypoint 接口和 `C_TaskQuest.GetQuestLocation` 未返回可用逐目标坐标；独立 `QuestPOIFrame` 的命中采样也未取得目标索引。这些是样本边界，不证明接口在所有任务上均无数据。当前采用已验证的任务级 POI 与有条件数据库补充。

## QuestieDB 适配

最初在线验证的数据库为 QuestieDB 1.0.15、Forever、baked、contract 4，22/22 个当时日志任务可查询；这不保证全部实体都有可导航位置。运行时动态检查数据库与契约，缺失、不兼容或读取失败不能破坏原生功能。

正式入口为 `LibQuestieDB.Quest/Npc/Item/Object`，别名为 `QuestDB/NpcDB/ItemDB/ObjectDB`；getter 使用点调用。使用 `RequireContract(4)` 检查兼容性。优先合成 getter，不写回修正，不复制整库，也不在每次刷新时遍历全库或建立全量名称索引。

- `objectives` 六组分别为 creature、object、item、reputation、kill-credit、spell；数据库组和排列不等于官方 `objectiveIndex`，creature 关联也不一定表示击杀要求。
- `startedBy` 包括 NPC、物件、物品；`finishedBy` 包括 NPC 和物件。数据库任务链只表示关系，不代表下一任务当前可接。
- 物品的 `npcDrops/objectDrops/itemDrops/vendors` 是不同来源关系。当前导航只追一层直接 NPC/物件来源，不递归容器或自动推荐购买。
- `GetAll` 返回带 `n` 的位置数组，可能包含 nil 槽；面向 JSON 时包装为命名字段。

位置与地图规则：

- `spawns` 键为 AreaID；记录为 `{x,y,phase?}`，原始坐标 0..100。保留原值并除以 100 转为归一化坐标。
- `waypoints` 比 `spawns` 多一层路径数组。地图适配使用 `Support.Get("ZoneDB").private` 中的映射，先基础表后 override。
- 映射在已验证版本中可能是数字赋值数据字符串；只受限解析数字条目，不执行字符串。子区域到祖先图可多对一，不能只用反向表的主 AreaID 过滤全部来源。
- 映射结果须验证客户端地图有效。已为 Forever 的数据不再重复执行 Era→Forever 转换。
- `(-1,-1)` 是副本哨兵，标为 `instance_only`；合法 `(0,0)` 不当成未知。缺坐标、缺映射、无效地图和副本位置分别表达原因。
- `phase` 保留原值，但未判定当前玩家可见性；带未判定相位的点不直接导航。`available` 只说明坐标可表达，不证明实体在场。

QuestieDB 的 baked 数据可能依赖启动时读取的 `.toc` 元数据，首次安装必须完整重启游戏。客户端解码函数解出的数据库内容仍是第三方数据。

## 逐目标对应与回退

官方目标表在既有普通任务样本中没有直接实体 ID 或坐标。当前匹配为 `task_scoped_exact_localized_text`：

1. 限定同一任务与目标类型，官方表有效且每条 `finished` 可读。
2. 仅采用普通 NPC/物件/物品关联。特殊组、非零特殊图标、重复引用、缺项或数量不一致时回退。
3. 使用客户端 `QUEST_MONSTERS_KILLED/QUEST_ITEMS_NEEDED/QUEST_OBJECTS_FOUND` 完整格式，将数据库实体全名与官方当前数量组成整条文字，要求逐字相等。
4. 全部目标必须构成唯一双射；不靠数组顺序、相似名字或数量独立推断身份。数据库条目第三槽是图标，不是目标数量。

这是一种有明确限制的任务内关联，不表示取得官方服务端实体 ID。身份映射完整也不保证位置可用，因此 `mappingComplete` 与导航 `mode` 分开表示。

NPC/物件目标用本体位置，物品目标追一层直接 `npcDrops/objectDrops`。每条剩余目标都须有可用静态位置，否则整任务回原生 POI。当前匹配最多 32 条目标，每目标最多 32 个来源、单来源最多 1200 个位置、任务总计最多 2400 个位置，超限回退。

可靠未完目标按 `questID + objectiveKey` 各安排一步；原生回退或整项交付每任务最多一步。`count` 是步骤数，`questCount` 是去重任务数；经验读取、参照与缓存重试按任务计一次。已完子目标不再导航，同地点仍服务其他未完目标时保留相应步骤。

## 过滤与交付

手动跳过、失败优先。进行中任务默认过滤副本、精英、专业；`includeEliteQuests=true` 仅放开精英。专业先用原生标签/分类，缺失时补 QuestieDB 技能要求；`suggestedGroup=0` 本身不足以排除副本。

整项官方完成后绕过活动类型过滤，按最新原生 POI 安排一个交付或待确认步骤。`ReadyForTurnIn` 为可交，只有 `IsComplete` 则等待确认，不用子目标计数替代整项状态。无原生位置、外图、无法转世界坐标仍保留排除原因，不用数据库交付点兜底或拉回旧刷怪点。

`N?` 与 `N~` 分别表示可交和待确认。`deliveryLocationConfirmed=false` 表示原生参考点未被证明是精确交付对象坐标。真正交付使任务从日志消失后才移除步骤，到点不算交付。

## 升级权重

进行中任务使用客户端相对难度：

| 档位 | 权重 |
| --- | --- |
| Trivial / Easy / Fair / Difficult / Impossible | 0.4 / 1.25 / 1 / 0.65 / 0.4 |
| 未知 | 1 |

不再按每低一级增加权重。任务经验显式传 `questID` 读取，只有 `HaveQuestData` 和 `HaveQuestRewardData` 均严格为 true 时，才接受有限、非负且可访问的 `GetQuestLogRewardXP` 值；这几个函数最初未被手册收录，已有在线存在性与只读调用验证，生产仍做类型和异常保护。缓存未就绪的零不是已知零经验。

参照只取已过滤、同图、Easy/Fair、已知正奖励的去重任务，至少 3 个才使用中位数。另用 `UnitXPMax` 的本级总经验作比例参照：

| 条件 | 经验因子 |
| --- | --- |
| 已知零经验 | 0.5 |
| 不足中位数 25% 或本级总经验 0.5% | 0.55 |
| 未触发上条，且不足中位数 50% 或本级总经验 1% | 0.8 |
| 正常收益或未知 | 1 |

两种参照取较低因子，不重复相乘。最终为难度权重 × 经验因子，再按直线距离 ÷ 最终权重排序；最大权重 1.25。已完成/待交任务难度权重为 1，经验因子最低 0.85。上述比例是路线策略，不代表服务端经验衰减或精确经验/小时。

## 导航保持与更新

| 参数 | 当前值 |
| --- | --- |
| 默认移动重排阈值 / 可设范围 | 100 码 / 10..5000 码 |
| 工作进入 / 退出半径 | 120 / 180 码 |
| 真实进展保护半径 / 窗口 | 300 码 / 90 秒 |
| 无进展强保护超时 | 180 秒 |
| 自动换 1 号所需收益 | 加权距离至少改善 30% 且减少 50 加权码 |
| 固定中心归组 / 原组延续范围 | 200 / 300 码 |
| 原位置大幅变化容差 | 100 码 |
| 位置、目标与奖励暂缺复查 | 各 5 秒，恢复后停止 |
| 玩家位置/导航与姓名板采样 / 地图绘制 | 0.5 秒 / 0.1 秒 |

移动阈值比较上次规划原点与当前位置的直线位移，不是累计路程；跨地图或升级不受该阈值限制。任务事件合并后刷新，相关加载事件可提前恢复数据。

`travel/working/turn_in/completion_pending/idle/unavailable` 表示当前导航状态，后续步骤为 `queued`。`working` 是附近工作推断，不代表客户端判定完成；无进展超时释放强保护，仍须满足自动切换门槛，不保证必换任务。

进展历史按目标 key 维护，并绑定真实增长时玩家附近的目标位置。其他目标或同实体远方刷新点不能继承当前区域的活动。已解析目标纯换序不重开计时；结构变化、计数回退、阶段变化或位置大幅跳变释放不适用的证明。数据暂缺不制造进展，恢复不重开已经超时的工作保护。

分组用首点固定中心，不链式扩张；原组延续按真实 `stepKey` 成员，不因同一任务关系插入远方兄弟目标。主动 `replan` 绕过本轮保持和旧组。工作计时不写 SavedVariables，启动/热加载重新建立导航会话。

## 热点与手动换点

世界坐标 3 码内去重，以 150 码空间格统计真实点周围密度，优先密集且邻居平均平方距离较小的真实点；中心至少相距 300 码。中心来自实际记录，不做跨区域平均或单链连通。有成群点时去孤立噪点，纯稀疏目标保留真实点兜底，不强造三处。

主点按既有直线/升级权重选择，最多两个备选不参与路线或里程。`pointCount` 是静态不同位置数，不是实时怪数、刷新速度或掉率。静态几何按目标/地图/位置版本缓存，最多 64 项；绘图不重算聚类，缓存不持旧目标进度。

换点仅限同一未完目标和当前地图。旧点 150 码固定圆内避开 600 秒，最多 64 条，按任务/目标/地图隔离；到期、跨图或目标结束清理，同 UI 热加载保留，不写盘。几何先按完整点集计算，再过滤避让中心，避免代表漂移绕回旧区。

切换采用草稿状态。重读时数据失效则保留原计划、序号、工作计时、避让与跳过，不发成功事件。切换后精确数据暂缺时等待恢复，不借原生 POI 绕回旧点；官方完成仍正常走交付。

## 地图、姓名板与设置生命周期

两图共享路线快照与悬停/点击逻辑，提示最多四行。编号像素避让和细线只改显示，不改真实坐标。大地图只在浏览玩家当前地区时绘制；小地图按实时半径、朝向裁剪，远处仅当前 1 号有边缘方向指示，中心留出角色箭头。Shift+M 尚待实机验证。

姓名板使用当前可访问的 `UnitCreatureID` 对照可靠身份索引，不缓存旧 ID 绕过身份限制。索引覆盖全部有效未跳过任务，身份与位置解析分开，缺刷新坐标不抹去可靠用途。击杀与一层直接 `npcDrops` 材料各保留进度，任一仍需就提示；未知/受限/错误、非活敌对 NPC 或 forbidden 框体隐藏，不以无匹配证明无关。

姓名板增删、任务更新和采样维护自有非交互图元，复用/移除/卸载清理旧引用，不改原生血条或 CVar。单位任务关系布尔值和 tooltip 枚举本身不足以判断某条子目标完成；当前不依赖未核实的 tooltip 任务行。

原生设置 `SetValueChangedCallback` 会累加监听，因此只注册一次回调，热加载更新当前分发函数，卸载关闭分发。`ns.route` 跨模块动态读取，换点草稿期间所有消费者使用同一状态；模块修改后按 `.toc` 顺序热加载整个插件。
