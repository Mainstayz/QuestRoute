# QuestRoute 技术说明

本文件保留仍适用于当前代码的数据约束和实现规则，替代按 r2–r13 分散记录的阶段调研。当前 `apiRevision=18`、`schemaVersion=1`；公开参数和返回字段以[插件 README](../addons/QuestRoute/README.md)为准，模块边界见[模块说明](../addons/QuestRoute/MODULES.md)。装备候选不改变任务路线，规则见[GEAR.md](../addons/QuestRoute/GEAR.md)。验证证据与未完成验收分别见[开发进度](../开发进度.md)和[待办事项](../待办事项.md)。

## 原生数据与位置语义

当前任务列表、原始目标文字、`finished`、计数、失败、整项完成和可交状态均以客户端为准。不用计数全满、到达坐标或数据库关系推断任务完成。

`C_QuestLog.GetQuestsOnMap(queryMapID)` 返回任务级 POI。其 `x/y` 属于**查询地图**，返回的 `poi.mapID` 可能仍是关联原图，必须分开保存：

| 字段 | 含义 |
| --- | --- |
| `coordinateMapID` | `x/y` 所属查询地图坐标系 |
| `reportedMapID` | API 返回的 POI 关联地图 |
| `x/y` | 归一化 0..1，显示常见地图坐标时乘 100 |
| `world.continentID/x/y` | 世界坐标，仅相同大陆可比较距离 |
| `source/precision` | `C_QuestLog.GetQuestsOnMap` / `quest_poi` |

原生回退和交付按 `reportedMapID` 判断目标归属，不能因邻图投影落在当前地图内就纳入；可靠细目标按静态位置本身的地图归属判断。世界坐标转换必须使用 `coordinateMapID`，不能只换地图标签。

POI 去重只合并同任务、同标记语义、同大陆且距离不大于 0.1 的点，优先原图记录作为固定代表，避免链式近邻误合并。没有世界坐标时只合并坐标系和坐标完全相同的记录。

未指定地图的查询扫描艾泽拉斯 947 的后代地图，不保证覆盖全部副本；根地图本身不保证返回所有点。POI 的 `inProgress`、`numObjectives` 不能判断真实进度。坐标可能随状态变化，不能永久缓存为实体刷新数据库。

既有普通任务样本中，waypoint 接口和 `C_TaskQuest.GetQuestLocation` 未返回可用逐目标坐标；独立 `QuestPOIFrame` 的命中采样也未取得目标索引。这些是样本边界，不证明接口在所有任务上均无数据。当前采用已验证的任务级 POI 与有条件数据库补充。

## QuestieDB 适配

最初在线验证的数据库为 QuestieDB 1.0.15、Forever、baked、contract 4，22/22 个当时日志任务可查询；这不保证全部实体都有可导航位置。运行时动态检查数据库与契约，缺失、不兼容或读取失败不能破坏原生功能。

正式入口为 `LibQuestieDB.Quest/Npc/Item/Object`，别名为 `QuestDB/NpcDB/ItemDB/ObjectDB`；getter 使用点调用。使用 `RequireContract(4)` 检查兼容性。优先合成 getter，不写回修正，不复制整库，也不在每次刷新时遍历全库或建立全量名称索引。

- `objectives` 六组分别为 creature、object、item、reputation、kill-credit、spell；数据库组和排列不等于官方 `objectiveIndex`，creature 关联也不一定表示击杀要求。
- `startedBy` 包括 NPC、物件、物品；`finishedBy` 包括 NPC 和物件。数据库任务链只表示关系，不代表下一任务当前可接。
- 物品的 `npcDrops/objectDrops/itemDrops/vendors` 是不同来源关系。当前导航只追一层直接 NPC/物件来源，不递归容器或自动推荐购买。
- `GetAll` 返回带 `n` 的位置数组，可能包含 nil 槽；面向 JSON 时包装为命名字段。

位置与地图规则：

- `spawns` 键为 AreaID；记录为 `{x,y,phase?}`，原始坐标 0..100。保留原值并除以 100 转为归一化坐标。
- `waypoints` 比 `spawns` 多一层路径数组。地图适配使用 `Support.Get("ZoneDB").private` 中的映射，先基础表后 override。
- 映射在已验证版本中可能是数字赋值数据字符串；只受限解析数字条目，不执行字符串。子区域到祖先图可多对一，不能只用反向表的主 AreaID 过滤全部来源。
- 映射结果须验证客户端地图有效。已为 Forever 的数据不再重复执行 Era→Forever 转换。
- `(-1,-1)` 是副本哨兵，标为 `instance_only`；合法 `(0,0)` 不当成未知。缺坐标、缺映射、无效地图和副本位置分别表达原因。
- `phase` 保留原值，但未判定当前玩家可见性；带未判定相位的点不直接导航。`available` 只说明坐标可表达，不证明实体在场。

QuestieDB 的 baked 数据可能依赖启动时读取的 `.toc` 元数据，首次安装必须完整重启游戏。客户端解码函数解出的数据库内容仍是第三方数据。

## 任务关联与有限前瞻（r16）

QuestieDB 是任务链、实体、接交与启动物品关系的来源，按其数据有效设计，不检查过时。客户端负责角色实时状态和实际接取/交付。`Discovery` 分批建立当前地图关联索引，移动及角色事件只刷新资格与局部候选；缺库、单条坏记录与不可读条件不能破坏原任务路线。来源无本图地点时也计入协程检查点；暂缺坐标按 5 秒间隔只重试受影响记录，恢复后补入索引并去重，不重扫整库。

**任务联想开关**：本节整套功能受按角色保存的 `associationEnabled`（boolean，默认 false；缺字段与非 boolean 脏值由 `RouteOptions` 纠正为 false，旧存档升级后因此变为关闭）控制。门控在三处，判定都是“字段 `== false` 才关闭”，字段缺失的内部直接调用（如直接调 `Collect` 的既有测试场景）视为开启：① `Planner` 在调用 `Discovery.Collect` 前检查 `settings.associationEnabled == false`，关闭时改用 `Discovery.Disabled()` 占位结果并清空 `announcedOpportunities`、`associationNotice`、`pickupChecks`、`gossip`；② `Discovery.Pump` 关闭时释放索引与 ID 列表并恒返回 false，重新开启由初始化重建索引（有延迟，完成后触发 `association_index_ready` 重建）；③ `Discovery.ObserveUnits/ObserveInteraction` 直接读角色存档判断，关闭时不记录观察、不产生 `pickup_unit_changed`。占位结果字段与 `Collect` 同名同型：`available=false`、`reason="association_disabled"`、`building=false`，`opportunities/announcedOpportunities/carriedItems/blocked/completed/quests` 为空表，`itemGate={required=0,unknown=0}`，`pendingCount/pendingLocationCount=0`，不带 `pendingQuestIDs`（因此 `ns.route.associationQuestIDs` 为 nil，不再监听任务数据回灌，也不发 `RequestLoadQuestByID`）。`Decision` 不受改动：它对不可用的关联数据原样返回不可用和同一 reason，故 `plan.decision.available=false`；路线中无 `pick_up/start_item` 步骤（`pickupCount=0`），不再发 `route.association`，地图接取机会图元为空。`plan.discovery`、`plan.decision` 字段始终存在，保持 `get_plan` 字段契约稳定。不受影响的层：`nextMapHint`（关闭后不再等待关联索引，可能比开启时更早出现）、进行中任务的刷新点/交付/热点图元、`switchNotice` 通知、姓名板与 `get_unit_tasks`、任务价值面板与 `analyze_quests`（它们不依赖 `Discovery`）。开关经 `SetRouteOptions` 写入并触发 `options_changed` 立即重建。

前置分 AND（preQuestGroup）和 OR（preQuestSingle），以角色已交付历史为准，`IsComplete/ReadyForTurnIn` 不代替交付。有符号或无法解释的条件保留未知。`nextQuestInChain` 是可见性约束：目标任务已接/已交可隐藏本任务，不能单独据其建立硬前置。所有当前可执行候选还要满足等级、种族/职业、互斥、技能/声望等适用条件。

`Decision` 对有限候选做宏动作束搜索，独立保留原 1 号及其实际热点的首动作基线。已接任务仍须通过规划资格过滤，跳过/失败不因已接身份而参与预测，但仍保留官方日志成员身份用于互斥等约束。收益扣除直线行程与粗略工作成本；不是时间/经验精确估算。可靠同目标按地域共享一次工作成本，不同目标同 NPC 来源只计部分协同，未知掉率不制造库存或完成材料。目标全覆盖且可交付时，预测中必须经过交付才能解锁后续；`triggerEnd` 探索/事件、外图、特殊或未覆盖目标不能被局部完成假设吞掉。

只将当前可执行的下一动作写进正式路线；预测未接任务、目标与交付保留在 `decision.predicted`，不更新日志、目标历史或姓名板。工作保护及手动热点优先；换点草稿不提前发关联提示。接取与物品启动有独立导航阶段，不进入清怪工作保护。实际接取、交付、背包和条件变化后重新计算。候选范围、搜索常量与返回字段集中见[插件 README](../addons/QuestRoute/README.md)。

接取建议须同时说明理由、位置和人物/物件类型；数据库资格通过仅表示预计满足，文字为“确认接取”，图元用 `N~!` / 独立黄色 `~!`；只有实际 NPC 提供的才用 `N!` / `!`，Decision 采用时称“建议先接”。取物来源也用 `~!`，复用两图悬停、避让和右键跳过；未采用建议不插入路线、不连线路，空路线仍显示。提示消失后可查地图或 `why`。真正显示过的接取/取物建议保存在当前地图会话中；Discovery 复用资格校验，离开即时范围后仅通过 `announcedOpportunities` 供地图和 `why` 查询，不把历史标点再当成新决策候选。返回范围内优先最新机会，避免重复；已接、已交、跳过、取得对应物品或其他明确阻挡时清除，元数据暂缺时隐藏并等待恢复。实际切图清空历史，浏览地图不清空，不写 SavedVariables。

`Discovery.ObserveInteraction` 在 `GOSSIP_SHOW/GOSSIP_OPTIONS_REFRESHED/QUEST_GREETING/QUEST_DETAIL` 读取可访问的 `UnitCreatureID("npc")`，把任务列表绑定该 NPC 和交互时玩家位置（`source=client, precision=interaction_position`）；不在重排时将残留 API 列表贴到新位置。Gossip 校验条数与每项任务 ID；旧式 greeting 只按该 NPC 的数据库任务全名唯一匹配，缺失或歧义不作否定；单任务详情只证明该项提供，不否定其他项。完整列表未提供的具体接取点从候选/历史提示中排除，其他未核验接取人仍可用；所有本图接取点均未提供时为 `unknown/npc_not_offering`，保留灰色 `×` 与原因，不能推测缺少哪项服务器条件。已有明确前置阻挡的后续仍可参与交付后的预测。对话关闭清当前确认；等级、接交/移除任务、背包、声望、技能/法术及世界/地区变化清观察，允许重核；这些观察仅存 UI 内存，不写 skipped 或 SavedVariables。

`Discovery.ObserveUnits` 复用 0.5 秒位置检查，读取 target/mouseover/softinteract 中数据库有任务来源的 NPC；只有身份可读、存活且 `UnitIsInInteractRange=true` 时，`UnitIsInteractable=false` 才记录 `npc_not_interactable`。不同接取人独立，当前真实对话不被通用交互标志覆盖；同一单位恢复可交互时解除此项观察并重排。太远、死亡、nil、机密或调用失败都不作否定。此状态同样保留灰色 ×、原因及位置，且遵守上述观察清理规则。

`startedBy` 中的物件可能只是任务物品来源。仅当目标物品明确不启动任务、只有一个直接物件来源且无 NPC 掉落，并与该物件身份一致时，分为 `possible_item_drop + questItem=true`，从可接地点移除；物品到任务的索引复用现有 byItem，背包读取仍区分 start_item 与已持有目标物品。背包持有后不再推荐拾取，`carriedItems` 提供真实 NPC 的接交参考（可为外图）；拿到物品不证明数量已齐、任务已接或可以交付。新取得的物品阶段可立即提示一次，随后背包事件保持静默。

## 逐目标对应与回退

官方目标表在既有普通任务样本中没有直接实体 ID 或坐标。当前匹配为 `task_scoped_exact_localized_text`：

1. 限定同一任务与目标类型，官方表有效且每条 `finished` 可读。
2. 仅采用普通 NPC/物件/物品关联。特殊组、非零特殊图标、重复引用、缺项或数量不一致时回退。
3. 使用客户端 `QUEST_MONSTERS_KILLED/QUEST_ITEMS_NEEDED/QUEST_OBJECTS_FOUND` 完整格式，将数据库实体全名与官方当前数量组成整条文字，要求逐字相等。
4. 全部目标必须构成唯一双射；不靠数组顺序、相似名字或数量独立推断身份。数据库条目第三槽是图标，不是目标数量。

这是一种有明确限制的任务内关联，不表示取得官方服务端实体 ID。身份映射完整也不保证位置可用，因此 `mappingComplete` 与导航 `mode` 分开表示。

NPC/物件目标用本体位置，物品目标追一层直接 `npcDrops/objectDrops`。每条剩余目标都须有可用静态位置，否则整任务回原生 POI。有效且相位可用的静态位置若暂时无法转世界坐标，返回 `world_position_unavailable`。第一次 5 秒后复查；若路线仍相同则改为 30 秒后再查，且不重复发送 `route.updated`，数据恢复后停止。不能只丢弃这些点、据其余点或外图原生 POI 推断本图已无目标。当前匹配最多 32 条目标，每目标最多 32 个来源、单来源最多 1200 个位置、任务总计最多 2400 个位置，超限回退。

可靠未完目标按 `questID + objectiveKey` 各安排一步；原生回退或整项交付每任务最多一步。`count` 是步骤数，`questCount` 是去重任务数；经验读取、参照与缓存重试按任务计一次。已完子目标不再导航，同地点仍服务其他未完目标时保留相应步骤。

## 过滤与交付

手动跳过、失败优先。进行中任务默认过滤副本、精英、专业；`includeEliteQuests=true` 仅放开精英。专业先用原生标签/分类，缺失时补 QuestieDB 技能要求；`suggestedGroup=0` 本身不足以排除副本。

未接任务统一在Discovery资格入口排除重复、战场/PvP、节日/安其拉筹备活动、捐献类、纯ASCII英文标题及低于minPickupLevel的任务，前瞻/即时机会/历史提示共用同一结果；已接任务先返回原有资格，不受这些接取过滤影响。重复沿用原生true或QuestieDB specialFlags最低位；战场使用原生类型41或数据库战场分类/AreaID，节日按明确zoneOrSort集合，捐献按“捐献/贡献”前缀。不是所有负数分类都属于节日，中文标题夹英文缩写仍保留。

minPickupLevel为按角色保存的0..60整数、默认15；0关闭等级过滤，等于阈值或0/-1/缺失等级保留。只比较数据库任务标注questLevel，不把最低接取等级requiredLevel混入；例如捐献毛料标注60、最低接取12，独立按捐献类排除。原生滑条、minlevel命令与SetRouteOptions共享验证/重排，get_plan.minPickupLevel返回当前值；无效输入原子拒绝，新控件需重载界面后在设置页可见。

战斗等级范围只依据任务怪/直接材料来源怪的等级，不比较任务标注等级；即使任务标注60级，只要所需怪符合限制也可安排，低等级任务的高等级怪仍须排除。NPC有效maxLevel（缺失时minLevel可证明超限）超过角色等级+maxMonsterLevelOffset时排除来源，reason为target_above_level；字段缺失、异常、不可访问或0/-1保持未知，不能据此声称安全。

maxMonsterLevelOffset是当前角色的0..5整数配置，默认2，0表示不高于自身。原生设置页滑条、monsterlevel命令和SetRouteOptions共用同一存储及校验，改值立即重排；数字类型/整数/范围验证失败不写任何字段。旧存档或损坏值补默认。滑条按控件判断注册、只保留一个回调分发，同一值的重复原生通知不重复重排；卸载清分发，热加载重绑当前命名空间。筛选缓存仅限本轮，不跨配置或玩家等级变化。仍不做职业/装备/队伍评分。

路线调用 Objectives 时传入玩家等级，先筛怪物来源再展开地点；同一物品允许其他适级来源，但一个必需目标没有可用来源时不能仅凭剩余目标预测整项完成。危险来源坐标失败不应抹去适级来源；已筛掉危险来源却无法定位允许来源时，不回退到无法识别怪物的原生 POI，暂缺 world 保留重试。Discovery 动态过滤原始索引、同步 targetsComplete 与资格，关联前瞻不能模拟已排除工作或解锁其后续；换热点使用相同路线解析。原始目标查询不传入路线等级限制，仍保留完整事实数据；接取和交付 NPC 不套战斗来源限制。

整项官方完成后绕过活动类型和等级过滤，按最新原生 POI 安排一个交付或待确认步骤。`ReadyForTurnIn` 为可交，只有 `IsComplete` 则等待确认，不用子目标计数替代整项状态。无原生位置、外图、无法转世界坐标仍保留排除原因，不用数据库交付点兜底或拉回旧刷怪点。

`N?` 与 `N~` 分别表示可交和待确认。`deliveryLocationConfirmed=false` 表示原生参考点未被证明是精确交付对象坐标。真正交付使任务从日志消失后才移除步骤，到点不算交付。

## 升级权重

进行中任务使用客户端相对难度：

| 档位 | 权重 |
| --- | --- |
| Trivial / Easy / Fair / Difficult / Impossible | 0.4 / 1.25 / 1 / 0.65 / 0.4 |
| 未知 | 1 |

不再按每低一级增加权重。任务经验显式传 `questID` 读取，只有 `HaveQuestData` 和 `HaveQuestRewardData` 均严格为 true 时，才接受有限、非负且可访问的 `GetQuestLogRewardXP` 值；这几个函数最初未被手册收录，已有在线存在性与只读调用验证，生产仍做类型和异常保护。缓存未就绪的零不是已知零经验。

参照只取已过滤、同图、Easy/Fair、已知正奖励的去重任务，至少 3 个才使用中位数。另用 `UnitXPMax` 的本级总经验作比例参照：

| 条件 | 经验因子 |
| --- | --- |
| 已知零经验 | 0.5 |
| 不足中位数 25% 或本级总经验 0.5% | 0.55 |
| 未触发上条，且不足中位数 50% 或本级总经验 1% | 0.8 |
| 正常收益或未知 | 1 |

两种参照取较低因子，不重复相乘。最终为难度权重 × 经验因子，再按直线距离 ÷ 最终权重排序；最大权重 1.25。已完成/待交任务难度权重为 1，经验因子最低 0.85。上述比例是路线策略，不代表服务端经验衰减或精确经验/小时。

### 剩余工作量系数（r15）

每个有键的未完目标再乘一个有界系数，用官方 `numRequired - numFulfilled` 估计还要做多少；它只微调排序，不是用时或经验/小时估算。

| 剩余数量 | 系数 |
| --- | --- |
| ≤ 2 | 1.10 |
| 3 ~ 6 | 1.00 |
| 7 ~ 12 | 0.95 |
| > 12 | 0.90 |

`progressbar` 类型、数值不可读/不可访问、目标已满、无法对应到目标或原生回退步骤一律为 1。步骤的 `priorityWeight` 为任务权重 × 该系数，任务级难度/经验权重和经验参照不变；`workFactor`/`remainingWork` 随步骤返回。

### 任务群加成（r15）

只在"自由选点"（没有组锚点，即选一个新组的起点或 `replan`）时生效。候选点 P 的有效权重为：自身权重 + 0.3 × Σ（P 周围 200 码内其他剩余步骤的权重，每个步骤只计一次），且不超过自身权重的 1.6 倍；得分仍为直线距离 ÷ 有效权重。组内续选、当前目标保护、原组延续和手动换点不使用加成，但"原目标 vs 新候选"的自动切换比较两边都用同一口径，所以移动中不会因口径不一致而误切换。

群组邻域使用本轮规划内复用的网格查询，格宽为邻域半径的两倍（400 码），只扫描相邻格，再按原有 200 码平方距离判定，避免浮点舍入造成边界漏算；收益仍按当前剩余步骤顺序各计一次，已选出的步骤不再贡献加成。设为 0 时不构建网格、不扫描邻域。网格不跨重排保存，不截断候选热点，也不改变原打分或并列选择规则。

它表达的是"先去收益密集的一片"，不保证总里程最短：孤立的近任务可能被放到最后。上限 1.6 倍使一个远处的大群不能压倒明显更近的任务。`weightedDistance` 含该加成；`levelingPriority.groupBonus`/`groupBonusCap` 给出当前参数。加成系数在 `Navigation.rules.groupBonus` 中，设为 0 即恢复纯加权最近。

### 下一张地图提示与切换提示（r15）

当前地图没有任何步骤、玩家世界坐标可用且没有等待恢复的位置/目标数据时，被排除的"目标在其他地图"任务中取离玩家最近的（同大陆按世界坐标，否则取第一个）作为 `plan.nextMapHint`（`questID/title/mapID/mapName`），`excluded[].otherMapID/otherMapName` 给出各自所在地图。数据暂缺不表示本图已做完；此时不推荐离开，待数据恢复后才允许提示外图。本建议不跨图规划。

路线切换提示（`UIErrorsFrame` 一行，同一内容同时用 `print` 写入玩家聊天框供回看）只在 1 号自动变化或本图做完时触发：`clearly_better_candidate` 为"已改为"，`previous_target_changed`/`continue_nearby_group` 为"下一站"，本图做完为"可前往"。启动、跨图及手动操作（重排、换点、跳过/恢复/清跳过、修改选项）不提示；同任务同动作在精确目标与原生 POI 间回退或恢复时，保留回退前已知目标用于比较：恢复到相同目标保持静默，暂缺期间真实完成后换到另一已知目标、整项转入交付仍可提示。外图建议在本图由有步骤变空、或等待数据后首次确认有外图建议时通知一次；同一目标不重复，两次提示至少间隔 8 秒；`switchNotice` 默认开启，同时控制 Toast 与聊天副本，按角色保存。任务关联提示也使用同一输出入口；聊天仅本人可见，Toast 不可用或报错仍只写一条聊天消息。`/questroute why` 只在玩家查询时列出排除原因。

## 客户端没有路线规划 API（2026-11-13 穷举确认）

在客户端 `2026.11.05.1` 手册与运行时双向核对（扫描全部 `C_*` 命名空间和 `C_Map` 40 个成员）：**不存在寻路、路网、多点排序或距离矩阵 API**。当前没有可用的真实路径代价数据；接取顺路插入仍按直线估计，不能据此声称有道路级路径规划。相关原生能力如下：

| API | 实际能力 | 对插件的作用 |
| --- | --- | --- |
| `C_Map.GetWorldPosFromMapPos` / `GetMapPosFromWorldPos` | 地图坐标 ↔ 世界坐标（`MayReturnNothing`） | **已在用**（`Core.lua` 的 `ToWorld`），不能绕开 |
| `C_Map.SetUserWaypoint` / `GetUserWaypoint` / `ClearUserWaypoint` | 玩家自己的地图路标 | 参数结构实测为 `{uiMapID=<number>, position=<Vector2D>}`（纯 table 也接受），手册查不到 `UiMapPoint`。**会直接覆盖玩家路标，无“只改我设的那个”这种粒度** |
| `C_Map.HasUserWaypoint` | 是否已设路标 | 没设路标时下面三个都返回 nil |
| `C_Navigation.GetNextWaypointForMap` / `GetTargetState` / `GetDistance` | 屏幕导航箭头的目标与距离 | 只有 `GetDistance` 可用；`GetNextWaypointForMap` 始终 nil。**`GetTargetState` 恒为 `Invalid`(0)，`GetFrame()` 虽然 shown、alpha 1、16×16 但 `GetNumRegions()`=0（无纹理），屏幕上不画箭头** |
| `C_QuestLog.GetNextWaypoint(questID)` / `GetNextWaypointForMap` / `GetNextWaypointText` | 某个任务的官方路标 | 只对已超级追踪且有官方 POI 的任务有效，否则全 nil |
| `C_SuperTrack`（21 个函数） | 控制“追踪中”的箭头内驱 | 玩家当前追踪 1069，`GetSuperTrackedQuestID` 可读；**不要替玩家改** |
| `C_TaxiMap.GetTaxiNodesForMap` | 飞行点列表（`name/nodeID/faction/isUndiscovered/position`） | 返回**全部地图**飞行点（38 个），`position` 是归一化大陆坐标，与插件 `world` 不同量级；仅可用于“附近有无飞行点”类提示 |
| `C_Map.GetMapLinksForMap` | 地图邻接关系 | **本客户端全为空表**（1442/1413/1414/1415/947 均为 0），不要用 |

当前路线继续基于直线距离加权重。真实路径代价需要另行取得或积累路网数据。

### 路线与提示的取舍

已完成的阶段计划不再单独维护；现行任务群加成、剩余工作系数、下一图建议与切换提示规则见上文。

| 方向 | 当前取舍 |
| --- | --- |
| 全局最优（TSP/2-opt） | 不做；当前目标需要稳定，且没有真实路径代价数据 |
| 按真实路径插入交付点 | 暂缓；不把现有直线顺路比较扩展为路网规划 |
| 当前目标光圈、后续步骤淡化 | 暂缓；视觉收益尚未实机确认 |
| 手柄跳过/换点按键绑定 | 暂缓、低优先级；保持少操作，不增加本期交互 |

任务群半径保留 200 码；已有单图样本不足以支持扩大，后续只在任务密集地图的现场验收发现问题时再调。原生屏幕箭头的否决依据如下，避免重复尝试已验证不可用的视觉层。

### 屏幕箭头为什么用不了（U4 否决依据）

2026-11-13 实机设过路标并开超级追踪，数据层全通、视觉层缺失：

| 检查 | 结果 |
| --- | --- |
| `C_Map.SetUserWaypoint` 写入 + `GetUserWaypoint` 读回 | 一致 |
| `C_SuperTrack.IsSuperTrackingUserWaypoint` | `true` |
| `C_Navigation.GetDistance` | 4218 → **383 码**（确实改指了 1 号热点） |
| `C_Navigation.GetTargetState` | **0 = `Invalid`**（`Occluded`/`InRange`/`Disabled` 分别 1/2/3） |
| `C_Navigation.GetFrame()` | shown、alpha 1、16×16，但 `GetNumRegions()` = **0**，没有纹理 |
| 截图 | 该坐标处只有背景，无箭头 |

结论：本客户端的原生导航箭头只有数据层、没有视觉层。想实现“不低头看小地图”只能自绘箭头（`GetDistance` + `GetPlayerFacing` 算角度），属于新功能，当前不做。

## 导航保持与更新

| 参数 | 当前值 |
| --- | --- |
| 默认移动重排阈值 / 可设范围 | 100 码 / 10..5000 码 |
| 工作进入 / 退出半径 | 120 / 180 码 |
| 真实进展保护半径 / 窗口 | 300 码 / 90 秒 |
| 无进展强保护超时 | 180 秒 |
| 普通目标自动换 1 号所需收益 | 加权距离至少改善 30% 且减少 50 加权码；关联前瞻另比较整段预测收益，仍遵守工作强保护 |
| 固定中心归组 / 原组延续范围 | 200 / 300 码 |
| 任务群加成 / 上限 | 0.3 倍其他步骤权重 / 自身权重的 1.6 倍 |
| 切换提示最小间隔 | 8 秒 |
| 原位置大幅变化容差 | 100 码 |
| 位置、目标与奖励暂缺复查 | 各 5 秒，恢复后停止 |
| 玩家位置/导航与姓名板采样 / 地图绘制 | 0.5 秒 / 0.1 秒 |

移动阈值比较上次规划原点与当前位置的直线位移，不是累计路程；跨地图或升级不受该阈值限制。任务事件合并后刷新，相关加载事件可提前恢复数据。

路线重建整体容错：单次重建中客户端读取或第三方数据抛错时，保留上一次成功计划、工作计时与跳过设置，聊天框提示一行并按 5 秒间隔由计时器统一重试，不逐帧重试；失败后到重试前，复查计时器、玩家移动/换图/升级和游戏事件等自动触发一律不再重建（意图保留，重试时统一补做），跳过、改设置、`replan` 等手动操作仍立即重建。重建次数（成功/路线未变/失败/未采用/拦截）、按原因分布和耗时记在 `ns.route.stats`，用 `/questroute perf` 查看；其中 `suppressed` 统计的是被退避拦下的调度节拍次数（驱动器约每 0.1 秒一次，一个未处理的 dirty 意图每个节拍都会计一次），不是被吞掉的事件数；数据库实体的刷新点展开结果（含外图点，`nextMapHint`/`otherMap*` 依赖）在 `Objectives` 内按 db 对象与版本跨次缓存，只缓存完整结果（世界坐标或地图信息暂缺、映射暂缺、空结果一律不缓存），上限 256 个实体、满后整体清空，db 或版本变化与 OnUnload 时作废；`get_plan`/`replan` 在尚无成功计划时返回 `ok=false`、`error.code="plan_unavailable"`，不虚构空计划。

`travel/working/turn_in/completion_pending/pick_up/start_item/idle/unavailable` 表示当前导航状态，后续步骤为 `queued`。`working` 是附近工作推断，不代表客户端判定完成；无进展超时释放强保护，仍须满足自动切换门槛，不保证必换任务。

进展历史按目标 key 维护，并绑定真实增长时玩家附近的目标位置。其他目标或同实体远方刷新点不能继承当前区域的活动。已解析目标纯换序不重开计时；结构变化、计数回退、阶段变化或位置大幅跳变释放不适用的证明。数据暂缺不制造进展，恢复不重开已经超时的工作保护。

分组用首点固定中心，不链式扩张；原组延续按真实 `stepKey` 成员，不因同一任务关系插入远方兄弟目标。主动 `replan` 绕过本轮保持和旧组。工作计时不写 SavedVariables，启动/热加载重新建立导航会话。

## 热点与手动换点

世界坐标 3 码内去重，以 150 码空间格统计真实点周围密度，优先密集且邻居平均平方距离较小的真实点；中心至少相距 300 码。中心来自实际记录，不做跨区域平均或单链连通。有成群点时去孤立噪点，纯稀疏目标保留真实点兜底，不强造三处。

主点按既有直线/升级权重选择，最多两个备选不参与路线或里程。`pointCount` 是静态不同位置数，不是实时怪数、刷新速度或掉率。静态几何按目标/地图/位置版本缓存，最多 64 项；绘图不重算聚类，缓存不持旧目标进度。

换点仅限同一未完目标和当前地图。旧点 150 码固定圆内避开 600 秒，最多 64 条，按任务/目标/地图隔离；到期、跨图或目标结束清理，同 UI 热加载保留，不写盘。有效手动热点在相同期限内优先于关联推荐，普通事件不解除选择；主动重排或目标完成、过滤、切图、到期后解除。几何先按完整点集计算，再过滤避让中心，避免代表漂移绕回旧区。

切换采用草稿状态。重读时数据失效则保留原计划、序号、工作计时、避让与跳过，不发成功事件。切换后精确数据暂缺时等待恢复，不借原生 POI 绕回旧点；官方完成仍正常走交付。

## 地图、姓名板与设置生命周期

两图共享路线快照与悬停/点击逻辑，提示最多四行。编号像素避让和细线只改显示，不改真实坐标。大地图只在浏览玩家当前地区时绘制；小地图按实时半径、朝向裁剪，远处仅当前 1 号有边缘方向指示，中心留出角色箭头。Shift+M 尚待实机验证。

姓名板使用当前可访问的 `UnitCreatureID` 对照可靠身份索引，不缓存旧 ID 绕过身份限制。索引覆盖全部有效未跳过任务，身份与位置解析分开，缺刷新坐标不抹去可靠用途。击杀与一层直接 `npcDrops` 材料各保留进度，任一仍需就提示；未知/受限/错误、非活敌对 NPC 或 forbidden 框体隐藏，不以无匹配证明无关。

姓名板增删、任务更新和采样维护自有非交互图元，复用/移除/卸载清理旧引用，不改原生血条或 CVar。单位任务关系布尔值和 tooltip 枚举本身不足以判断某条子目标完成；当前不依赖未核实的 tooltip 任务行。

原生设置 `SetValueChangedCallback` 会累加监听，因此只注册一次回调，热加载更新当前分发函数，卸载关闭分发。`ns.route` 跨模块动态读取，换点草稿期间所有消费者使用同一状态；模块修改后按 `.toc` 顺序热加载整个插件。
